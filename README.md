HeartGuard is an evidence-informed, full-stack clinical machine learning web application that predicts cardiovascular disease risk from 13 physiological and electrocardiographic biomarkers. Built with **Python 3.11**, **Flask**, **scikit-learn**, and **Chart.js**, the application provides interactive risk scoring, a semi-circular speedometer gauge, factor impact explanations, and a production-ready JSON REST API.

## 🎯 Project Overview

Heart disease remains the leading cause of global mortality. Early, non-invasive risk stratification allows healthcare practitioners to prioritize preventive interventions. HeartGuard implements an end-to-end machine learning pipeline trained and evaluated on the **UCI Cleveland Heart Disease dataset** (303 patient records, 13 clinical features).

The system compares three competitive ML architectures:
1. **Regularized Logistic Regression** (L2 penalty, liblinear solver)
2. **Random Forest Classifier** (Ensemble of 100 decision trees)
3. **XGBoost Classifier** (Gradient-boosted decision trees)

Models are evaluated on an 80/20 stratified holdout test split. The champion model is selected by **Area Under the Receiver Operating Characteristic (ROC-AUC)**, serialized as an offline pipeline artifact, and served through a responsive web interface and REST API.

---

## ✨ Key Features

- **Automated ML Pipeline (`train.py`)**: End-to-end preprocessing, median/mode imputation for missing fluoroscopy (`ca`) and thalassemia (`thal`) values, standard scaling, and one-hot encoding.
- **Explainable Predictions**: Quantifies feature attributions (model coefficients / weights) to explain *why* a patient is flagged as Low, Moderate, or High risk.
- **Interactive Risk Speedometer (Chart.js)**: Semi-circular doughnut gauge indicating estimated risk probability with color stops:
  - 🟢 **Low Risk**: `< 30%`
  - 🟡 **Moderate Risk**: `30% – 70%`
  - 🔴 **High Risk**: `> 70%`
- **Instant Patient Presets**: Quick one-click buttons to load a healthy clinical profile or an at-risk profile for testing.
- **Full Physiological Validation**: Client- and server-side range checks prevent impossible physiological inputs.
- **Production REST API (`/api/predict`)**: JSON endpoint for programmatic integration with hospital records or telemedicine apps.
- **Privacy First**: Stateless in-memory inference. Zero patient data is stored or logged.

## 📊 Model Benchmark & Performance

All models were evaluated on the exact same 80/20 stratified test split (242 training instances, 61 holdout test instances: 33 disease-free, 28 disease-positive).

| Model Architecture | Accuracy | Precision | Recall | F1-Score | ROC-AUC | Status |
| :--- | :---: | :---: | :---: | :---: | :---: | :---: |
| **Logistic Regression** | **88.52%** | **83.87%** | **92.86%** | **88.14%** | **96.65%** | ⭐ **Champion Model** |
| **XGBoost** | 91.80% | 87.10% | 96.43% | 91.53% | 95.24% | Evaluated |
| **Random Forest** | 85.25% | 82.76% | 85.71% | 84.21% | 94.26% | Evaluated |

### Test Confusion Matrix (Champion: Logistic Regression)
```
                    Predicted Negative    Predicted Positive
Actual Negative            28                     5          (Specificity: 84.8%)
Actual Positive             2                    26          (Sensitivity / Recall: 92.9%)
```

### Top Influencing Clinical Biomarkers
1. **Coronary Fluoroscopy (`ca_0.0`)**: 0 major vessels colored strongly decreases risk (-1.50).
2. **Chest Pain (`cp_4.0`)**: Asymptomatic presentation correlates with silent ischemia (+1.03).
3. **Thallium Scintigraphy (`thal_7.0`)**: Reversible defect indicates stress-induced ischemia (+0.82).
4. **Biological Sex (`sex_1.0`)**: Male sex shows higher demographic cohort baseline (+0.69).
5. **ST Slope (`slope_2.0`)**: Flat exercise ST slope indicates repolarization abnormality (+0.60).

## 🧪 Dataset Specification

The Cleveland clinic database is the standard benchmark for cardiology machine learning:
- **Total records:** 303 patients
- **Class distribution:** 164 No Disease (54.1%), 139 Disease Present (45.9%)
- **Data storage:** `data/heart.csv` (bundled inside repository for 100% offline reproducibility)

### 13 Input Features:
1. `age`: Patient age in years (18 – 120)
2. `sex`: Biological sex (1 = Male, 0 = Female)
3. `cp`: Chest pain type (1 = Typical angina, 2 = Atypical angina, 3 = Non-anginal, 4 = Asymptomatic)
4. `trestbps`: Resting blood pressure on admission (80 – 240 mm Hg)
5. `chol`: Serum cholesterol in fasting state (100 – 600 mg/dl)
6. `fbs`: Fasting blood sugar > 120 mg/dl (1 = Diabetic threshold, 0 = Normal)
7. `restecg`: Resting ECG results (0 = Normal, 1 = ST-T wave abnormality, 2 = LV hypertrophy)
8. `thalach`: Maximum exercise heart rate achieved (60 – 220 bpm)
9. `exang`: Exercise-induced angina (1 = Yes, 0 = No)
10. `oldpeak`: ST depression induced by exercise relative to rest (0.0 – 10.0 mm)
11. `slope`: Peak exercise ST segment slope (1 = Upsloping, 2 = Flat, 3 = Downsloping)
12. `ca`: Number of major coronary vessels colored by fluoroscopy (0 – 3)
13. `thal`: Thallium scintigraphy (3 = Normal, 6 = Fixed defect, 7 = Reversible defect)

## 🌐 REST API Reference

### Predict Endpoint: `POST /api/predict`
Accepts a JSON payload containing the 13 clinical features and returns probability, risk tier, and top contributing factors.

#### Request Example:
```bash
curl -X POST http://127.0.0.1:5000/api/predict \
  -H "Content-Type: application/json" \
  -d '{
    "age": 67,
    "sex": 1,
    "cp": 4,
    "trestbps": 160,
    "chol": 286,
    "fbs": 0,
    "restecg": 2,
    "thalach": 108,
    "exang": 1,
    "oldpeak": 2.5,
    "slope": 2,
    "ca": 3,
    "thal": 7
  }'
```

#### Response Example (HTTP 200 OK):
```json
{
  "status": "success",
  "prediction": 1,
  "prediction_label": "Presence of Heart Disease",
  "risk_probability": 0.997,
  "risk_percentage": 99.7,
  "risk_level": "High",
  "risk_tier_description": "Significant risk factors detected across key physiological markers. Prompt clinical evaluation is strongly advised.",
  "top_factors": [
    {
      "code": "cp_4.0",
      "impact": "increases_risk",
      "is_risk": true,
      "score": 1.03,
      "text": "Chest Pain (Asymptomatic (Silent)): Clinical marker correlating with ischemic presentations"

    {
      "code": "thal_7.0",
```

## 💻 Local Development Setup

### 1. Prerequisites
- Python 3.11+
- Git

### 2. Clone the Repository
```bash
git clone https://github.com/11249a422-tech/heartguard.git
cd heartguard
```

### 3. Create & Activate Virtual Environment
```bash
# Windows
python -m venv venv
venv\Scripts\activate

# macOS / Linux
python3 -m venv venv
source venv/bin/activate
```

### 4. Install Dependencies
```bash
pip install -r requirements.txt
```

### 5. Train the Model Pipeline (Optional)
The pre-trained champion pipeline is already committed at `model/heart_model.pkl`. To retrain:
```bash
python train.py
```

### 6. Run the Web Application
```bash
python app.py
```
Open [http://localhost:5000](http://localhost:5000) in your browser.

## 🚀 Deployment on Render

This repository includes native **Render Blueprint** configuration (`render.yaml`), `Procfile`, and `runtime.txt`.

### Step-by-Step Deployment Instructions:
1. Push this repository to your GitHub account (`https://github.com/<your-account>/heartguard`).
2. Log in to [Render](https://dashboard.render.com/).
3. Click the **"New +"** button in the top navigation bar.
4. Select **"Blueprint"**.
5. Connect your GitHub account and select the **`heartguard`** repository.
6. Render will automatically detect `render.yaml` and configure:
   - **Service Name:** `heartguard`
   - **Environment:** `Python` (`python-3.11.9`)
   - **Build Command:** `pip install -r requirements.txt`
   - **Start Command:** `gunicorn app:app`
   - **Instance Plan:** `Free`
7. Click **"Apply"**.
8. Wait 1–2 minutes for the build and container startup. Once complete, your live web service will be active at `https://heartguard.onrender.com`!
